Key verification notes

Soroban state archival (drives 9 verdicts). Expired persistent/instance entries are archived, not deleted: any transaction whose footprint touches an archived entry fails until the entry is restored (RestoreFootprintOp — anyone can pay), and restoration returns the original value. Contract code never observes an archived entry as missing, so unwrap_or-based “takeover / funds lost / cap reset / claim erased” scenarios do not occur. The genuine residual is availability, addressed by a hot-path TTL-extension sweep, a keeper re-pin duty, and a restore runbook (R-1).
Overflow posture (drives 5 verdicts). contracts/Cargo.toml sets overflow-checks = true for release builds: arithmetic overflow traps and reverts — it never wraps. Two findings asserted silent wrapping while a third (from the same scan) correctly stated the opposite. Trap reachability is bounded far below i128 range by min-collateral, leverage, position-size and deposit caps.
Existing mitigations the scan under-weighted. The vault factory ships a tested launch gate (leader allowlist + max-vaults cap) that closes the unbounded-list findings via ceremony config; market entrypoints enforce positive collateral and bounded size at every path feeding volume recording; the shim's deployed backend mode is Noeracle-native, making the SEP-40 TWAP issue latent until an admin flips modes.
