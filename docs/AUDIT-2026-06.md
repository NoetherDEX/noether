# Noether Full-Project Audit — June 9, 2026

**Scope:** entire repo at branch `staging` (commit `3d2ae8a`), which is what production (noether.exchange) runs since the 2026-06-08 cutover to the Noeracle stack.
**Method:** 16-agent multi-agent audit — 11 subsystem deep-dives (every finding carries file:line evidence), 4 web-research sweeps (competitor landscape, perp risk management, Stellar/Soroban ecosystem, mainnet launch playbook), and a completeness-critic pass.
**Result:** 87 findings (12 critical) + 40 research insights + prioritization.
**Companion artifact:** `TASKS.md` at repo root — the actionable, phased task list derived from this report.

Severity legend: `critical` = funds at risk / security hole / solvency threat / hard mainnet blocker · `high` · `medium` · `low`.
Effort legend: `hours` / `days` / `week+`. `[known]` = was already documented in CLAUDE.md / KNOWN_ISSUES.md.

## Executive summary

Noether is a solid testnet product with real engineering strengths: a clean cumulative-funding model applied consistently across isolated/cross/liquidation paths, correct deci-bps fee-tier math, complete `require_auth` coverage on every contract entry point, no secrets in git history, resumable fail-loud blue-green deploy scripts, and a well-architected SDK/indexer/API skeleton.

It is **not yet safe for mainnet**. The blockers cluster in three areas:

1. **Oracle trust** — anyone can set prices today via two independent paths (Noeracle's unauthenticated persistent write entrypoint, and the router relaying caller-supplied publisher keys), and the market accepts any price with zero deviation bound. This is a $0-cost vault drain (strictly worse than the Mango/GMX/JELLY exploit class).
2. **Solvency** — no aggregate OI cap or payout reservation against the vault; LP NAV ignores open trader PnL (`update_unrealized_pnl` is dead code) enabling LP front-running; a winning trader's close can hard-revert when PnL exceeds vault USDC; no insurance fund.
3. **Incident response** — the market contract can never be paused or upgraded (entry points removed for WASM size); one admin EOA is USDC+NOE issuer, admin of all contracts, deploy key, and the faucet hot key inside Vercel; the keeper (sole oracle publisher + liquidator) dies silently with no alerting, timeouts, or failover.

**Decisions taken 2026-06-09 (founders):** no fixed mainnet date — apply to the SCF Audit Bank once the blocker list is cleared; oracle remains **Noeracle-only** (hardened), with Chainlink / Pyth-via-Wormhole added as cross-checks when they ship on Stellar; **lean mainnet v1** — 3 pairs at 10x with deposit/OI caps and allowlist, deferring `vault_factory` and on-chain referral payouts to v1.1.

## Part 1 — Subsystem findings (87)

### 1. Market contract (`contracts/market/src` + `contracts/noether_common/src`)

*Assessment: well-structured for testnet; cumulative-funding model clean and consistently applied; fee-tier deci-bps math correct and well-tested; cross-margin aggregation uses checked arithmetic. For mainnet: no kill switch or upgrade path, oracle trusted with no sanity bound, stop orders corrupt cross-margin accounting, no aggregate solvency/OI controls.*

#### M-1 · No pause and no upgrade path — the kill switch is dead code — `critical · days`
`require_not_paused()` is checked everywhere, but pause/unpause entry points were removed for WASM size and `set_paused` is only ever called with `false` at init (`lib.rs:165`). The market can NEVER be paused. There is also no admin/config update or WASM upgrade hook, so any bug fix requires a full redeploy, stranding every position, order, and cross-margin balance.
- Evidence: `market/src/lib.rs:165` (`set_paused(false)`); `lib.rs:642` ('pause/unpause removed'); `require_not_paused` at `lib.rs:210,669`; `storage.rs:89`; no `update_current_contract_wasm` anywhere.
- Fix: re-fit WASM budget to add admin-gated `pause()`/`unpause()` and an `upgrade(wasm_hash)` entry point (`env.deployer().update_current_contract_wasm`). Drop view helpers if needed for size. `pause()` is non-negotiable for a fund-holding exchange.

#### M-2 · Market trusts oracle price with zero deviation/sanity bound — `critical · week+ · [known]`
`get_oracle_price` only checks staleness and `price > 0` — no deviation cap or circuit breaker. The configured `max_oracle_deviation_bps` is dead code. Combined with the unhardened Noeracle write path, an attacker self-signs an arbitrary price, calls open/close/liquidate directly (market entry points are public; router is bypassable), and drains the vault via fabricated PnL.
- Evidence: `market/src/lib.rs:2058-2082`; `types.rs:177-178,198` (`max_oracle_deviation_bps` unused); `noether_router/src/lib.rs:26-31` docstring 'anyone can set the price'.
- Fix: harden the Noeracle write path (see O-1) AND independently add a market-side guard in `get_oracle_price`: reject moves beyond a per-asset band vs a stored last-good price using the already-present `max_oracle_deviation_bps`.

#### M-3 · Stop/take/trailing orders on cross-margin positions execute via the isolated path — `high → critical (critic) · hours`
`set_stop_loss`/`set_take_profit`/`place_trailing_stop` never check `margin_mode`, so they attach to cross positions. On trigger, `execute_close_order` pays collateral+PnL to the trader's WALLET and never calls `remove_cross_margin_position` — funds escape the shared pool, leaving sibling positions under-collateralized. Separately, manual `close_position` never cancels linked SL/TP, leaving zombie Pending orders.
- Evidence: `market/src/lib.rs:1334,1436,1941` (no margin_mode guard); `execute_close_order` `lib.rs:2259-2344`; `close_position` `lib.rs:385-401` vs `lib.rs:2332-2333`.
- Fix: reject `margin_mode==1` in the three order-attach functions (or route execution through the cross close path). Add SL/TP removal to `close_position` and `close_position_cross`.

#### M-4 · No aggregate OI cap or reservation — vault-as-counterparty solvency gap — `high → critical (critic) · week+ · [known]`
`check_vault_liquidity` calls `reserve_for_position(size)`, which is check-only with no actual reservation, so unlimited positions each pass against the same liquidity. No per-asset OI or skew cap. Winners can become unpayable: `settle_pnl` reverts when pnl > vault USDC, so the trader cannot realize profit. Keepers earn nothing on underwater positions; no insurance fund — bad debt sits on LPs.
- Evidence: `market/src/lib.rs:233,2084-2096`; `vault/src/lib.rs:417-443`; vault revert at `lib.rs:314`; keeper reward gating `market/src/lib.rs:476-480`; `lib.rs:1071-1081`.
- Fix: tracked global/per-asset OI caps enforced in open paths (using existing `total_long/short_size`) sized to vault AUM; insurance fund + flat liquidation incentive funded from collateral (see Part 2, risk parameter sheet).

#### M-5 · Global AllPositions/AllOrders Vec rewritten on every trade — O(n) scaling ceiling — `high → medium (critic, at guarded-launch scale) · week+ · [known]`
Every open/close reads, dedup-scans, and rewrites the single AllPositions ledger entry (same for AllOrders). One shared, growing entry gates ALL trading; at a few thousand live positions it hits Soroban entry-size/CPU limits and open_position fails for everyone.
- Evidence: `market/src/storage.rs:206-246, 248-280, 366-408`; keeper iteration via `get_all_position_ids` `lib.rs:627`.
- Fix: paginated buckets or counter + per-id existence keys; drop the global list from the hot path. Re-architecture — schedule at traction, after the blockers.

#### M-6 · Reduce-only opens a new opposing position instead of reducing, via an O(n) scan — `medium · days`
A reduce-only limit entry only checks an opposing position exists, then opens a brand-new opposite position — double fees, two liquidation surfaces, contrary to the reduce-only contract. The check scans every position in the market.
- Evidence: `market/src/lib.rs:2155-2178` → falls through to normal open at `lib.rs:2206-2238`.
- Fix: actually offset the trader's opposing position (reduce/close + refund remainder); index via `TraderPositions(addr)`.

#### M-7 · Market never reports unrealized PnL to vault; funding only accrues when poked — `medium · days`
`vault.update_unrealized_pnl` has zero callers, so vault AUM/NOE price ignore open-position PnL (see V-2). Funding is fully lazy: the cumulative rate only moves when permissionless `apply_funding()` is called, and it applies the *current* imbalance retroactively across the whole elapsed window.
- Evidence: zero callers repo-wide; vault AUM `vault/src/lib.rs:693`; `apply_funding` `market/src/lib.rs:565-607`.
- Fix: call `update_unrealized_pnl` on open/close + keeper cron; enforce/document hourly `apply_funding` cadence or snapshot imbalance at intervals.

#### M-8 · On-chain referral discount hook still missing; stale KNOWN_ISSUES entries — `low · days · [known]`
The market fee path never calls `referral.record_trade`. Also: C-1 documented open but fixed in code (see corrections).
- Evidence: `market/src/lib.rs:62-101`; KNOWN_ISSUES.md:208-213 vs `lib.rs:1054-1063`.
- Fix: bundle the referral hook into the pause/upgrade WASM refit (deferred to v1.1 per scope decision); update KNOWN_ISSUES/CLAUDE.md now.

### 2. Vault + Vault Factory (`contracts/vault`, `contracts/vault_factory`)

*Assessment: per-function logic mostly sound — `math.rs` pure/checked/well-tested, settlement auth thoughtfully designed, 5% leader-skin invariant correct in isolation. Two architectural gaps are hard blockers for their features: factory commingles funds, and LP NAV never sees open PnL.*

#### V-1 · Factory commingles all vaults' USDC; `sync_total_usdc` reads whole-contract balance (cross-vault drain) — `critical · week+` *(deferred feature → v1.1 gate)*
Every vault's deposits sit at the single factory address; each leader trade sets that vault's `total_usdc` to the factory's ENTIRE USDC balance. With >1 vault, one vault absorbs others' funds — depositors can withdraw against inflated NAV and drain other vaults. The factory is the sole market trader for all positions, so a leader can also close any other vault's position. Likely root cause of the two known-failing `leader_*` tests.
- Evidence: `vault_factory/src/lib.rs:580-585`, `:328`, `:354`, `:137-141`; ownership check `market/src/lib.rs:336-339`.
- Fix: track per-vault `total_usdc` by deltas (subtract collateral on open, add measured settlement return via per-call balance diff); persist vault_id→position_id map and reject leader ops on foreign positions; long-term, isolate funds per vault.

#### V-2 · LP vault NAV ignores open trader PnL (`update_unrealized_pnl` is dead code) → LP front-running — `critical · week+`
AUM = total_usdc + fees − unrealized_pnl, but unrealized_pnl stays 0 forever. When traders hold large open gains, an LP can withdraw at stale-high NAV before settlement, offloading the loss onto remaining LPs (and symmetrically). The counterparty-pricing core is wrong.
- Evidence: `vault/src/lib.rs:393-408`, `:685-701`; zero callers repo-wide.
- Fix: market calls `update_unrealized_pnl` on every open/close/liquidate, or `get_noe_price` computes aggregate open PnL via a market view. Until then, gate/pause LP withdrawals; do not ship NOE pricing to mainnet as-is.

#### V-3 · Vault oversubscription + solvency cliff; losses booked without verifying receipt — `high · week+`
`reserve_for_position` locks nothing, so combined max payouts can exceed AUM; when a winner's pnl exceeds vault USDC, `settle_pnl` reverts and the winner is frozen. The pnl<0 path credits `total_usdc` for the full loss even when the market transfers less (cross-margin bad debt), inflating NAV above real assets.
- Evidence: `vault/src/lib.rs:417-443`, `:309-325`, `:333-340` vs `:367-385`; `market/src/lib.rs:1071-1080`.
- Fix: make reservation real (accumulate committed payout; reject opens beyond AUM − reserved; release on close). Insurance-fund/partial-socialization path so a winning close can't hard-revert. Credit losses only up to funds actually received.

#### V-4 · Factory withdrawal liveness: open-position collateral excluded from vault NAV — `high · days` *(v1.1)*
A vault's `total_usdc` counts only idle USDC at the factory; collateral deployed into open positions is never valued. Depositors can redeem only their share of idle cash; deposits/withdrawals mid-trade misprice shares.
- Evidence: `vault_factory/src/lib.rs:199-212`, `:580-585`; no open-position valuation anywhere.
- Fix: include open-position value (collateral + unrealized PnL via market query) in NAV; interim: block deposits while positions are open.

#### V-5 · Single global high-water mark causes profit-share equalization unfairness — `medium · week+` *(v1.1)*
HWM is one NAV per vault, not per depositor: late joiners get charged 10% on gains earned before they joined; entrants below HWM ride the recovery fee-free; leaders can time deposits around `claim_leader_fees`.
- Evidence: `vault_factory/src/math.rs:90-115`; `lib.rs:96`, `:492-493`.
- Fix: per-depositor cost basis (equalization/series accounting); lighter interim: force `claim_leader_fees` before every deposit/withdraw.

#### V-6 · Vault TTL uses a seconds value (2,592,000) for both threshold and extend, on every write — `medium · hours · [known]`
`extend_ttl` takes ledgers, not seconds — 2.59M ledgers ≈ 150 days, and threshold==extend forces a top-up on nearly every call. Market uses 17,280/518,400.
- Evidence: `vault/src/storage.rs:119,128,137,146,180`.
- Fix: match market convention; define shared TTL constants in `noether_common`.

#### V-7 · `profit_share_bps` hardcoded at 10%; `MAX_PROFIT_SHARE_BPS` cap is dead code — `low · hours` *(v1.1)*
- Evidence: `vault_factory/src/lib.rs:99`; `types.rs:17`; no enforcement/setter.
- Fix: add a validated `create_vault` param + leader setter (≤ MAX), or delete the constant and document 10% fixed.

### 3. Oracle stack (`noeracle_shim`, `noether_router`, keeper push path, api/web reads)

*Assessment: read/display path clean and well-documented; the shim is a correct minimal SEP-40 translator; the router elegantly collapses Soroban's one-op-per-tx constraint into atomic verify-then-trade; `docs/noeracle-feature-requests.md` is an unusually honest threat model that correctly names S-1 as the mainnet gate. The trust/write path is the dominant risk.*

#### O-1 · Noeracle persistent write path is unauthenticated (anyone can set any price) — `critical · week+ · [known]`
The keeper writes via `update_ed25519_persistent` and the shim reads exactly that slot. Per the team's own audit, that entrypoint verifies the ed25519 sig against a CALLER-SUPPLIED pubkey with no is_publisher/staleness/monotonic guard. Anyone can store BTC=$1, then open/liquidate against it — direct vault drain. THE documented mainnet gate.
- Evidence: `docs/noeracle-feature-requests.md:14-62` (S-1); `noeracle_shim/src/lib.rs:111-120`; `scripts/keeper/src/stellar.ts:71-89`.
- Fix (Noeracle repo): registered publishers + staleness + monotonic-round checks on the persistent entrypoint (or hardened `update_batch_ed25519_persistent`, P0-1); feature-gate benchmark stubs out of deployed wasm. Reference design = Pyth: trust lives in a t-of-n signed payload (start 2-of-3 publisher keys on separate infra), relaying stays permissionless, 500ms cadence unaffected. Hard release gate.

#### O-2 · `noether_router` relays caller-supplied publisher keys — trades are self-priceable — `critical · days · [known]`
`refresh_price` forwards trader-supplied pubkeys/sigs straight into `update_ed25519_persistent`, then calls the market which re-reads that slot. The router stores no publisher allowlist. A trader can self-sign a fake price, open cheap, close rich — atomically, in the deployed prod router.
- Evidence: `noether_router/src/lib.rs:40-47, 96-98, 188-207`; `web/lib/stellar/noeracle.ts:63-71` + `market.ts:90-97`.
- Fix: store an allowed publisher pubkey set at `initialize` (+ admin setter); reject foreign keys in `refresh_price`. Redeploy + re-init. Defense-in-depth only — full safety still needs O-1 (attackers can bypass the router).

#### O-3 · Liquidations/order-exec can't refresh price — stale slot freezes them, growing bad debt — `high · days · [known]`
The router only exposes open/close_with_price. Keeper `liquidate`/`liquidate_cross_account`/`execute_order` call the market directly and depend on the heartbeat staying inside the 60s window; if it lags, liquidations revert #30 exactly during volatility while users can still self-close via the router.
- Evidence: `noether_router/src/lib.rs:82,111`; `scripts/keeper/src/stellar.ts:145-154,247-256,222-231`; handoff doc §5.
- Fix: add `liquidate_with_price` and `execute_with_price` to the router (mirror `close_with_price`); switch the keeper to them.

#### O-4 · No TWAP / manipulation-resistant mark for liquidation and funding — `high · week+ · [known]`
Liquidation checks and funding read a single instantaneous price. One wick (or a single O-1 poke) can liquidate healthy positions or skew funding. Noeracle overwrites the latest entry, so no consumer can compute a TWAP.
- Evidence: `docs/noeracle-feature-requests.md:114-122` (P1-4); `market/src/lib.rs:2061-2074`.
- Fix: Noeracle `prices(asset,n)` ring buffer + `twap(asset,n)`; market uses TWAP for liquidation triggers and funding, spot for entry/exit display. Rides the next full-stack redeploy; sequence after O-1.

#### O-5 · Single-keeper liveness SPOF: no RPC failover, tight staleness budget, no alerting — `high · days · [known]`
One Railway keeper keeps every pair fresh; config reads a single `RPC_URL` (the CLAUDE.md failover claim is doc/code drift). Push cadence (30s interval + 4s/asset sleeps + up to 30s confirm-poll) can approach the 60s window per asset under stress. No heartbeat alarm — a dead keeper silently freezes trading and liquidations.
- Evidence: `scripts/keeper/src/config.ts:47,71-72`; `index.ts:277-278`; `stellar.ts:449-457`.
- Fix: implement `SOROBAN_RPC_URLS` failover in the keeper; parallelize per-asset push; freshness alarm (Noeracle P3-8 `last_update` or watchdog). Warm standby keeper for mainnet.

#### O-6 · Shim has no read-time staleness guard — display consumers show frozen prices as live — `medium · days · [known]`
`shim.lastprice` returns the slot verbatim with no age check. The market's own 60s check protects trades, but the api oracle ticker and web on-chain `getPrice` will render an hours-old price as current if the keeper dies.
- Evidence: `noeracle_shim/src/lib.rs:98-121`; `api/src/services/oracle.ts:37-53` + `oracleTicker.ts:47-68`; P1-5.
- Fix: include price age in api oracle payloads; 'stale price' banner in web past a threshold; optionally `lastprice_fresh(max_age)`.

#### O-7 · Keeper circuit breaker is bypassed on boot and absent on the router path — `medium · hours`
The 50% jump filter compares against in-memory `currentPrices` — empty after every restart, so the first attestation per asset is pushed unchecked; the filter is self-referential; the router path has zero price-sanity checks.
- Evidence: `scripts/keeper/src/index.ts:50, 247-254`; `noether_router/src/lib.rs:188-207`.
- Fix: seed the breaker from the on-chain slot (or a reference quote) before first push; absolute per-asset sanity bounds; coarse min/max bound in router/shim as backstop.

#### O-8 · Symbol→tag map and asset list hardcoded and duplicated across shim + router — `low · days`
The 3-asset map is copy-pasted in both contracts; adding a pair requires redeploying BOTH and keeping the maps byte-identical; drift = silent mispricing. Directly blocks the '10+ pairs' goal.
- Evidence: `noeracle_shim/src/lib.rs:201-217` and `noether_router/src/lib.rs:251-267`.
- Fix: move tag derivation into `noether_common` (single source) or an admin-set asset→tag registry; cross-contract test asserting map equality.

### 4. Referral system (contract + gateway + web) and fee-tier preview

*Assessment: read pipeline genuinely solid (small contract, checked arithmetic, correct market-only auth on record_trade, 13 passing tests; indexer decoder matches event tuples; post-G-1 public/gated split sensible). The entire economic write path is non-functional end-to-end, and the live page promises money flows that cannot happen.*

#### R-1 · `claim()` zeroes claimable but transfers no USDC — earnings burn with no payout — `critical → medium if deferred (critic; v1.1 decision) · days`
`claim()` sets claimable=0 and emits an event; contracts cannot react to events and no keeper watches it. The referral contract stores no USDC address and holds no funds. The moment `record_trade` accrual ships, every claim permanently destroys earned balances.
- Evidence: `contracts/referral/src/lib.rs:197-214`; `types.rs:38-60`; `web/components/referral/ClaimFeesCard.tsx:62`.
- Fix: add `usdc_token` to `initialize()`; market transfers payout USDC to the referral contract in `record_trade`; `claim()` performs the actual transfer. Must land in the same redeploy as the market hook — never ship accrual without payout. **v1.1 scope; meanwhile disable claim UI.**

#### R-2 · `record_trade` is never called and no discount is applied anywhere — entire earn/discount loop is dead; G-2 describes nonexistent gateway code — `high · week+ · [known]`
Market sends 100% of fees to the vault with zero referral references; router and keeper never call `record_trade`. KNOWN_ISSUES G-2's claim that 'the gateway applies the discount' is false — no fee/discount calculation exists in api/, tx-builders, or SDKs. The advertised 4%/10% is marketing copy while `/referrals` is live in production.
- Evidence: `market/src/lib.rs:292-293, 871-874, 2240-2243`; `api/src/services/referral.ts:98-177` (read-only); KNOWN_ISSUES.md:175-181; `ReferralBanner.tsx:174`.
- Fix: execute the planned hook in the market fee path (cross-contract `record_trade`, apply returned discount, transfer payout) — **v1.1**. NOW: correct KNOWN_ISSUES G-2 and soften the `/referrals` + banner copy so the 4%/10% claim isn't false advertising.

#### R-3 · `min_code_volume` enforced nowhere — permanent code namespace is free to squat — `high · days`
`create_code` performs no volume check; `MinCodeVolume` storage and `InsufficientVolume` error are dead code; the client-side allowlist is build-time only and trivially bypassed on-chain. Codes are permanent and first-come-first-served ('noether', influencer handles). The page explicitly claims 'the contract enforces a 14-day trading volume threshold' — false.
- Evidence: `contracts/referral/src/lib.rs:72-112`, `:249`; `web/app/referrals/page.tsx:49`; `CreateCodeCard.tsx:19-20,34-40`.
- Fix: enforce on-chain (admin co-auth for beta, or market-view volume check bundled with the redeploy); add admin `revoke_code`; fix the UI copy either way.

#### R-4 · Indexer at-least-once delivery double-counts claimable and wipes referrer counters on replay — `medium · hours`
`persistRaw` dedups by event_id but `applyEvent` always runs; cursor written after the batch. Replays re-increment claimable/total_earned and duplicate rows; replayed `code_created` uses INSERT OR REPLACE which resets counters to 0.
- Evidence: `indexer/src/handlers/referral.ts:14` vs `:31-114`; `poll.ts:108-111`.
- Fix: skip applyEvent + bus emit when persistRaw rowsAffected==0; `ON CONFLICT DO UPDATE` preserving counters; audit market/vault handlers for the same pattern (see I-2).

#### R-5 · Sybil self-referral trivially recaptures 14% of fees once the hook ships; no revoke/unbind/pause controls — `medium · days` *(v1.1)*
Only direct referrer==referee is blocked; a second wallet self-refers. No admin tools exist (no revoke, unbind, pause) — abuse is unstoppable post-deploy short of redeploying.
- Evidence: `contracts/referral/src/lib.rs:117-139`, surface `lib.rs:34-283`; `storage.rs:147-153`.
- Fix: add `revoke_code`, `unbind_referee`, `set_paused` before the hook ships; keep referrer share modest; monitor projections for self-funding loops.

#### R-6 · OrderPanel fee preview baseline always $0 — `get_trader_volume` not public; client-side volume resets on refresh — `medium · days · [known]`
`getTraderFeeInfo` simulates a nonexistent view; error swallowed → volume14d=0; client-side accumulation lost on refresh while the contract charges from true on-chain volume — quoted fee/tier diverges for any tier-1+ trader.
- Evidence: `web/lib/stellar/market.ts:1271-1287`; `OrderPanel.tsx:117-119,314,338`; `market/src/lib.rs:62-86`.
- Fix: serve volume from the indexer — add public `GET /v1/account/volume?address=` summing 14-day notional; OrderPanel fetches on mount + after trades; drop the client accumulator.

#### R-7 · web `lookupCode` calls nonexistent `lookup_code` — availability check always shows '✓ available' — `low · hours`
The contract view is `resolve_code`; the simulation error is swallowed and null = 'available'. Users discover collisions only via failed tx (#8).
- Evidence: `web/lib/stellar/referral.ts:83` vs `contracts/referral/src/lib.rs:230`; `CreateCodeCard.tsx:65-66`.
- Fix: rename the method string to `resolve_code`; distinguish simulation failure from 'code free'; optional fallback to `/v1/referral/lookup`.

#### R-8 · `total_volume_generated` accumulates fees, not volume — stat ~2000x understated — `low · hours`
`record_trade` adds `original_fee` into `total_volume_generated` (its own unit test confirms); indexer mirrors it; UI renders as 'Cumulative referee trading volume'.
- Evidence: `contracts/referral/src/lib.rs:176-179` (test `:441`); `indexer/src/handlers/referral.ts:80-94`; `ReferralStats.tsx:27-30`.
- Fix: add a `volume` param when the signature changes for the hook; or rename field + label to 'Fees Generated'.

### 7. Indexer (`indexer/src` + migrations)

*Assessment: genuinely good skeleton — capture/projection separation, PK-deduplicated events_raw, proper migration runner, forward-compatible decoders, boot-time vault reconciliation, real tests. Verified: router/shim emit no events of their own — router-mediated trades ARE fully captured via market events. Core problem is delivery semantics.*

#### I-1 · Malformed event decode wedges the poller in a duplicate-applying poison loop — `high · hours`
A decoder throw escapes pollOnce before writeCursor; loop() retries the same batch every 2s forever — indexing stalls AND every event before the poison one re-applies non-idempotent updates ~30x/min. Conversely, handler errors are swallowed and the cursor advances (silent drops). Both directions wrong.
- Evidence: `poll.ts:89-106, 108-114, 61-64`; `decoders/scval.ts:23-38`; `router.ts:41-47`.
- Fix: per-event try/catch → dead_letter table (event_id, error, raw XDR) and keep advancing; rethrow/dead-letter handler failures so the cursor halts instead of dropping. Vitest with a malformed payload.

#### I-2 · Projection handlers are not idempotent despite at-least-once delivery — `high · days`
Redelivery re-applies relative UPDATEs (vault `total_usdc += …`), increments `referred_count` on duplicate bindings, resets lifetime stats via INSERT OR REPLACE, and duplicates activity rows (no UNIQUE constraints). Migrations 006-009 are the existing drift-repair history.
- Evidence: `handlers/vault.ts:92-135`; `handlers/referral.ts:33-59, 61-94`; migrations 003/004; `poll.ts:108-114`.
- Fix: use events_raw INSERT OR IGNORE rowsAffected as the idempotency guard; migration adding UNIQUE keys; ON CONFLICT DO UPDATE preserving counters; wrap each event's writes in a transaction.

#### I-3 · No gap detection, retention-window handling, or RPC failover — downtime silently loses events — `high · days`
RetentionState (oldestLedger) ignored; a stale cursor past retention either errors permanently (manual Turso surgery) or silently resumes past a hole; cold-start lookback can itself exceed retention; only rpcUrls[0] used.
- Evidence: `rpc.ts:26-61`; `poll.ts:69-77, 119-122`; `config.ts:25`.
- Fix: rotate through rpcUrls on transient failures; on out-of-range, clamp to oldestLedger, record skipped range in a ledger_gaps table, log error; warn when cursor nears retention edge.

#### I-4 · Zero observability; single-writer not enforced; addresses baked into Docker image — `medium · days`
No health endpoint/metrics/alerts. contracts.json is COPY'd at build (env vars can't re-point — D-3 misleading). Railway deploy overlap can briefly run two pollers double-applying relative updates.
- Evidence: `indexer/src/index.ts`; `indexer/Dockerfile:36`; `packages/shared/src/contracts.ts:41-70`; `cursor.ts:26-38`.
- Fix: /healthz reporting cursor lag (Railway healthcheck); env-var overrides in loadContracts; compare-and-swap cursor writes, stop on CAS failure.
